# Antivirus Lab

## Description

A Bash-based antivirus daemon that monitors a directory for changes, detects suspicious files, and moves them to a quarantine directory.

The project also includes a restore utility that allows users to review quarantined files, restore falsely flagged files, or permanently delete them.

## Project Structure

```text
Lab2/
├── antivirusd.sh
├── restore.sh
├── test.sh
├── Makefile
├── README.md
├── monitored/
├── malicious_dir/
├── directory-info.last
└── directory-info.new
```

### Main Files and Directories

- `antivirusd.sh`: Monitors the source directory, detects changes, scans files, and quarantines suspicious files.
- `restore.sh`: Lists quarantined files and allows users to restore or permanently delete them.
- `test.sh`: Used for testing file detection.
- `Makefile`: Provides targets for creating the quarantine directory and running the scripts.
- `README.md`: Documents the project and explains how to use it.
- `monitored/`: Directory monitored by the antivirus daemon.
- `malicious_dir/`: Directory where suspicious files are quarantined.
- `directory-info.last`: Stores the previous directory snapshot.
- `directory-info.new`: Stores the latest directory snapshot.

The snapshot files are generated by the daemon and may not exist before the first run.

## Requirements

- Ubuntu Linux
- Bash
- GNU Make

### Installing Requirements on Ubuntu

Update the package lists:

```bash
sudo apt update
```

Install GNU Make:

```bash
sudo apt install make
```

Check the installed versions:

```bash
bash --version
make --version
```

Bash is normally available by default on Ubuntu.

## Setup

Navigate to the project directory:

```bash
cd ~/Desktop/OS/Lab2
```

Make the scripts executable:

```bash
chmod +x antivirusd.sh restore.sh test.sh
```

Create the quarantine directory using the Makefile:

```bash
make
```

This creates `malicious_dir/` if it does not already exist.

Ensure that the source directory `monitored/` exists before running the scripts.

## Running the Antivirus Daemon

Run the daemon using:

```bash
make daemon
```

The daemon performs an initial scan when it starts, then checks the monitored directory every five seconds.

To run it directly with custom arguments:

```bash
./antivirusd.sh monitored/ malicious_dir 5
```

The arguments are:

1. `monitored/`: Source directory to monitor.
2. `malicious_dir`: Destination directory for quarantined files.
3. `5`: Interval in seconds between checks.

Press `Ctrl+C` to stop the daemon.

## Detection Rules

The required detection rules are defined inside the `scan_directory()` function in `antivirusd.sh`.

### Flagged Extensions

The extension list is defined in the `case` statement:

- `.exe`
- `.bat`
- `.vbs`
- `.scr`
- `.ps1`

### Flagged Keywords

The keyword list is defined in the `grep -qiE` command:

- `virus`
- `trojan`
- `malware`
- `worm`
- `ransomware`

Keyword matching is case-insensitive.

A file is considered suspicious if its extension matches one of the flagged extensions or its contents contain one of the flagged keywords.

When a suspicious file is detected, the daemon copies it into `malicious_dir/` and deletes the original from `monitored/`.

## Restoring Quarantined Files

Run:

```bash
make restore
```

Alternatively, run the restore script directly:

```bash
./restore.sh monitored/ malicious_dir
```

The script lists the files in the quarantine directory and allows the user to choose a file and one of the following actions:

1. Restore the file to the monitored directory.
2. Permanently delete the file from quarantine.
3. Leave the file unchanged and return to the file list.

If the quarantine directory is empty when the tool starts, it displays:

```text
No malicious files to review
```

## Makefile Targets

| Command | Description |
|---|---|
| `make` | Creates `malicious_dir/` if it does not exist. |
| `make daemon` | Runs the antivirus daemon. |
| `make restore` | Runs the restore utility. |
| `make clean` | Removes the generated directory snapshot files. |

To remove the snapshot files:

```bash
make clean
```

The daemon recreates the snapshots when it runs again.

## Important Notes

- The monitored directory should contain files directly, without nested subdirectories.
- The daemon and restore utility should not run concurrently.
- Restored files may be detected again by the daemon if they still match a detection rule, unless a whitelist feature has been implemented.
- Cron scheduling and whitelist functionality are optional bonus features and should only be considered implemented if they have actually been completed.
